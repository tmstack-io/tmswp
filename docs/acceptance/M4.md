# M4 受け入れ記録

実施日: 2026-06-13

## 対象

M4: Support / View / Log / ActionRouter

## 実装範囲

- `Support\Arr` / `Support\Str` / `Support\Html` を実装し、ドット記法、文字列変換、HTML属性/classレンダリングを文書07の収載メソッドに限定して追加した。
- `Log\LogChannel` / `ScopedLog` / `LoggerRegistry` / `SimpleLogger` を実装し、PSR-3 v3、channel/scope/level配信、WP向けファイル出力、保護ファイル生成、ローテーションを接続した。
- `View\TemplateLocator` / `Template` / `View` / `ActionRouter` / `NotFound` を実装し、テンプレートfallback、隔離include、actions戻り値契約、404シグナル、`tms_var()`を接続した。
- `KernelConfig::theme(actions: false)` とテーマ専用 `ActionRouter` 登録、プラグインboot時の `templates/` fallback登録を `Kernel` に統合した。
- actions規約検査として `TMSWP\Core\PHPStan\Actions\NoOutputRule` / `NoSet404Rule` を追加した。これらは自動有効化用 `extension.neon` には登録せず、`starters/theme/phpstan-actions.neon` から明示利用する。
- `packages/core/bin/tms-check` の孤児actions検査をユニット・直接CLI実行で固定した。

## 受け入れ基準チェック

- ✔ `Arr::get()` / `has()` / `set()` / `only()` / `first()` / `wrap()` のドット記法・null存在判定・非配列中間上書きをユニットテストで固定した。
- ✔ `Str::replace()` / `stringify()` / `truncate()` / `convertEol()` / case変換 / `excerpt()` の主要仕様をユニットテストで固定した。
- ✔ `Html::attributes()` / `classes()` の先頭スペース規約、boolean属性、配列class、`esc_attr` 境界をユニットテストで固定した。
- ✔ `LoggerRegistry` は channel/scope/level配信と明示設定後のdefault再生成なしを検証した。
- ✔ `SimpleLogger` は保護ファイル生成、日付/level別ファイル出力、context JSON、例外追記、maxFilesローテーションを検証した。
- ✔ `TemplateLocator` は slug検証、子テーマ→親テーマ→fallback順、重複fallback抑止、解決キャッシュflushを検証した。
- ✔ `Template::render()` は `$args` のみが見える隔離includeと、例外時の出力バッファ清掃を検証した。
- ✔ `View::set()` のマージ、`View::get()` / `tms_var()`、null値の存在判定を検証した。
- ✔ `ActionRouter::dispatch()` は非対象素通し、親actions採用、array→View、NotFound→404、debug時の不正戻り値警告、`$template` 無加工返却を検証した。
- ✔ `Kernel` はテーマ形態のActionRouter登録、`actions: false` による無効化、プラグイン形態のTemplate fallback登録を検証した。
- ✔ actions PHPStanルールは echo/print/printf/print_r(false)/exit/inline HTML と `$wp_query->set_404()` を検出し、`wp_safe_redirect()` 直後の `exit` を許可することをRuleTestCaseで固定した。
- ✔ `bin/tms-check` はWP関数・Composer autoloadに依存せず、孤児actionsだけをCLIで検出する。

## 追加確認

- `NoOutputRule` / `NoSet404Rule` は `packages/core/extension.neon` へ登録していない。通常のPHPStan解析へ誤適用せず、actions専用設定からのみ利用するため。
- `ActionRouter` と `Template` のinclude対象パスは内部スタックで保持し、includeスコープには actions では `$wp_query`、template では `$args` だけが見えるようにした。
- WordPressテスト環境では既に `init` が発火済みのため、統合テスト中に `Kernel::boot() was called after the 'init' hook had fired` のログが出る。既存M2/M3同様、`debug=false` のcatch-up経路を検証対象として扱っている。

## 未達・要確認

- `composer test:coverage` はローカルPHPに coverage driver が無いため失敗。Unit本体は `OK (84 tests, 290 assertions)` だが、`No code coverage driver available` のPHPUnit警告でexit 1。CIでは pcov を使う想定。
