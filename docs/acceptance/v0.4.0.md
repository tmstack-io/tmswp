## 3. 実装内容の要約

- 状態機械・送信トークン・キャッシュ・スパム対策(T1)
  - 確認画面の無いフォームは`open()`で使い捨ての送信トークン(SubmitToken)を埋め込み、確認画面ありのフォームはConfirmTokenのjtiに一本化した。トークンは`base64url(正準JSON).HMAC-SHA256`で、鍵は用途(confirm-token・submit-token)ごとにHKDFで派生させる(TokenSigner)。
  - `JtiStore::claim()`はJtiClaim(Claimed・Duplicate)を返し、データベースのエラーは例外にする。onCompleteの例外では、debugは例外を投げ、本番はFormのKernelのロガーに`error`で記録して汎用の送信失敗のエラーを出し、jtiを手放して同じトークンで再送できる。
  - 確認トークンの値を、claimの前に今の規則で検証し直す。ファイルの存在の確認と全項目の復元も、claimの前に行う。
  - `handle()`と`open()`で`nocache_headers()`と`DONOTCACHEPAGE`を付ける。SpamGuardInterfaceと`FormDefinition::spamGuard()`を足し、honeypotとTurnstileの手本をrules/form.mdに置いた。
  - CSRFの失敗・改ざん・再送の拒否・ファイルの消失・onCompleteの例外をログに残す。文脈には、フォームのIDと例外のクラス名・投げられた場所(ほかに項目名・スパム対策のクラス名)だけを入れる。
  - `applyDefaults()`は、`handle()`の後の呼び出しと、未知の項目・形の違う値を例外にする。ConfirmTokenStatusをTokenStatusに改名した。
- リクエスト取り込みと描画(T2)
  - `FormRequest::fromGlobals()`は例外を投げない。数値のキー、配列のファイル、不正な形のファイルのエントリ、不正なUTF-8の入力は、その項目のエラーにする(noticeで記録し、文脈には項目名だけを入れる)。
  - `open()`のaction、入力のid、`labelTag()`のforを上書きでき、FWが決める属性(method・enctype・name・checked等)の指定は`FormConfigException`にする。
  - パスワードの項目は、再描画・確認画面・トークンに出さない。確認画面ありのフォームに置いたら、定義の時点で例外にする。`Form::confirmFields()`・`FormDefinition::hideOnConfirm()`・チェックボックスの`checkedLabel`を足した。
  - `FormHtml::escHtml()`を削除し、`esc_html()`を直接呼ぶ。
- ファイル(T3)
  - 確認画面の有無にかかわらず、受け取ったファイルをTempFileStoreに保管し、onCompleteには常にStoredFileを渡す。確認画面なしは「値の検証 → claim → 保管 → onComplete」の順で、保管に失敗したらjtiを手放す。
  - onCompleteが正常に終わったら、消費されなかった一時ファイルを消す。例外の時は消さない(再送で使える)。完了の後の削除の失敗は`error`で記録し、送信は成功のまま返す。
  - `JtiStore::isClaimed()`を足し、一時ファイルが消えた後の確認トークンの再送(完了画面のリロード)を再送として拒否する。
  - gcはWP-Cronの毎時のイベント(TempFileGc)だけで行う。初めての保管でスケジュールし、最後のKernelが無効になったときに解除する。
  - 保存名を固定の`file`にし、クライアントのファイル名はメタデータにだけ記録する。`.htaccess`はApache 2.4と2.2の両方の構文にした。`toAttachment()`はフロントでもwp-admin/includesを読み込んでから`media_handle_sideload()`を呼ぶ。
  - CIの修正(`45e47c5`):`TempFileStore::deleteDirectory()`を、本体の`file` → `meta.json` → 残りのファイル → ディレクトリの順に固定した。`UploadedFile::detectedMime()`の判定の失敗は、`application/octet-stream`にせずTempFileExceptionにする。
- 検証とルール(T4)
  - メッセージの解決を`Messages::resolve(RuleInterface, ...)`に一本化した。Callback・Retype・暗黙の選択肢も`tmswp/form/rule_message`フィルタと`{label}`の置換を通る。フィルタの文字列以外の戻り値と、Callbackのboolと文字列以外の戻り値は`FormConfigException`にする。
  - 単一のチェックボックスの`checkedValue`との一致、複合フィールドの部品の暗黙の選択肢、複数選択に直接渡した文字列を検証する。`RequiredIf::equals`をcheckboxesの値に対応させ、`MaxFileSize::mb()`にmessageの引数を足した。
  - UploadFileルールを削除した。`Form::validate()`は、入力の不正 → アップロードの失敗 → 規則のエラーの順にする。trimの`preg_replace`の失敗は例外にし、Messages・Rule/の`function_exists`による黙った代替を無くした。
- フォームのレシピ(T5)
  - rules/form.mdを、13項目・確認画面あり・完了画面へのPRG・メールの完全な例に書き直した。PRGはテンプレートの先頭で明示的に呼ぶ前処理のクラスで行い、`wp_safe_redirect()`の直後の`exit`を`00-overview.md`原則1の例外として書いた。確認画面なしの例、ファイルの受け取り(nginxの設定、独自の一時保管の場所の`gc()`の登録)、ページキャッシュとの関係、カスタムのRule、Requiredを先頭に置く規約、スパム対策も書いた。
  - rules/form-mail.mdを新設した。ヘッダインジェクションの対策、自動返信、送る前の添付ファイルの読み取りの確認、送信の失敗時のログと再送を書いた。
- 受け入れテスト(T6)
  - docs/05の受け入れ基準の全項目にテストを対応させた(5.2の条件の後の表)。FormRuleTest・FormHtmlTest・FormStructureTestを新設し、`10-quality.md` §8.1の旧テストを移植した。
  - `Field::checkbox()`の空の`checkedValue`を`FormConfigException`にした(未チェックの`''`と区別できず、Requiredが常に失敗するため)。
  - 統合テストの後始末(Kernelのレジストリの復元、HTTPのfixtureが作ったjtiとWP-Cronのイベントの削除)と、統合テストのtestdoxの出力を足した。EntityFacadeIntegrationTestのアイキャッチありのサムネイルを、GDで作ったJPEGで確かめるテストにした。
- Urlルールの国際化ドメイン名(`05e7fb0`・`f45f4ce`)
  - ホスト名に非ASCIIの文字があれば、ホスト名の部分だけを`idn_to_ascii()`(UTS #46)で変換してから`filter_var`で判定する。ホスト名の`_`、変換できないホスト名、パス・クエリの非ASCIIは不合格のまま。入力値は書き換えない。
  - ext-intlが無い環境では、Urlのコンストラクタが`FormConfigException`を投げる。coreはext-intlを`suggest`に書き、ルートのcomposer.jsonは`require`に足した。

## 6. 次の版へ引き継ぐ事項

- **settings-pageの`OptionFormBridge::applyDefaults()`が、optionの値(mixed)をそのまま`Form::applyDefaults()`に渡す。** v0.4.0で`Form::applyDefaults()`は文字列(multipleの項目は文字列のlist)以外の値を`FormConfigException`にしたため、int・boolのoptionを結ぶと例外になる。既にある「persistのキャスト」(Formの値からoptionへの向き)と重ならないよう、optionからFormへの向きの変換をv0.7.0-T1の完了条件に書き足した。
- **docs/08 §2の設定ページのテンプレートの例に、旧いForm APIの名前(`renderHiddenFields()`)が残っている。** v0.7.0-T1の完了条件に書き足した。
- **rules/actions.mdが、旧来の`actions/<template>.php`と`tms_var()`の方式のままで、明示呼び出し方式(§1.10)と食い違う。** v0.5.0-T1の完了条件に書き足した(対象ファイル領域に既にある)。
- **tools/extract-rules-code.phpのクラス名の正規表現が、`final readonly class`に一致しない。** このファイルを対象ファイル領域に持つv0.8.0-T6の完了条件に書き足した。
- **例外をログの文脈に渡す箇所。** v0.4.0のFormは、ログに例外のクラス名と投げられた場所だけを入れる。ほかの箇所を`packages/*/src`で探し、次を見つけた。
  - packages/core/src/Kernel/Kernel.phpの613〜618行(フックのメソッドの例外を本番で`'exception' => $exception`で記録する)。Kernel.phpを対象ファイル領域に持つv0.5.0-T4の完了条件に書き足し、対象ファイル領域に「フックのメソッドの失敗のログ」とKernelTest.phpを加えた。
