# M1 受け入れ記録

実施日: 2026-06-13

## 対象

M1: Kernel / Container / Discovery

## 実装範囲

- `Kernel\KernelConfig` / `Kernel\Kernel` / `KernelContext` を実装し、テーマ・プラグイン両方の boot API と lifecycle hook 登録を固定した。
- `Container\Container` を PSR-11 実装として追加し、共有インスタンス、Closure factory、クラス名束縛、単段 alias、autowiring、循環依存検出を実装した。
- `Discovery` / `DiscoveryResult` / `DiscoveredComponent` / `DiscoveredHookMethod` / `ComponentCache` を追加し、`appDir` 限定の Attribute 走査、メソッドレベル `#[Action]` / `#[Filter]` 収集、決定的ソート、PHP ファイルキャッシュを実装した。
- `ComponentAttributeInterface`、コア属性マーカー、`Action` / `Filter`、M3 以降で使う Meta / Option 関連属性のシグネチャを追加した。
- `Hook\Hook` / `HookInitializer` を追加し、`#[AsHook]` の `register()` 例外経路とメソッド属性経路を分離した。
- M1 の boot に必要な最小限の `View\ActionRouter` / `View\NotFound` / `Log` を追加した。詳細挙動は M4 / M7 で実装する。
- M0 の core ダミークラスを削除し、スターターの boot 呼び出しを `TMSWP\Core\Kernel\Kernel` に更新した。

## 追加確認

- `.php-cs-fixer.dist.php` は `final_class` と文書 02 の「例外クラスは final にしない」指定が衝突するため、`packages/core/src/Exception/` を fixer 対象から除外した。
- `ComponentCache::load()` は warm path で app クラスをロードしないため、キャッシュ payload の class 文字列に対して `class_exists()` 検証を行わない。実在検証はコールド走査またはフック発火時の Container 解決で行う。
- 本番相当の `validateMtimes=false` では文書 02 通り mtime 検証を行わず、キャッシュ clear 契機に依存する。

## 未達・要確認

- `composer test:coverage` は M0 と同じくローカル PHP に coverage driver が無いため未実施。CI では pcov を使う想定。
- `AsPostType` / `AsTaxonomy` / `AsUserRole` / `AsModel` / `AsOptionGroup` の実処理は後続マイルストーン担当。M1 では誤って初期化された場合に `UnsupportedComponentException` で停止する。
