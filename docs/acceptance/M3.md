# M3 受け入れ記録

実施日: 2026-06-13

## 対象

M3: meta / option 層 + PHPStan 拡張

## 実装範囲

- `Meta\ObjectType` / `MetaStorageInterface` / `WpMetaStorage` / `MetaSchemaDefinition` / `MetaSchemaSet` / `MetaSchemaRegistry` / `ValueCaster` / `MetaBag` を実装し、`#[MetaSchema]` 付き定数の収集、検証、`register_*_meta` 登録、型付き読み書きを接続した。
- `#[UseMetaStorage]` と `#[WithMetaRevisions]` を実装し、エンティティ単位のstorage差し替えと `revisions_enabled` 登録を `MetaSchemaRegistry` に統合した。
- `OptionStorageInterface` / `WpOptionStorage` / `OptionSchemaDefinition` / `OptionSchemaSet` / `OptionRepository` / `OptionRepositoryFactory` / `OptionAccess` / `OptionGroupInitializer` を実装し、backed enum + `#[AsOptionGroup]` / `#[OptionSchema]` のoption宣言を接続した。
- `PostType::meta()` / `Taxonomy::meta()` / `UserRole::meta()` を `MetaSchemaRegistry` 経由に更新し、各Initializerからschema登録するよう接続した。
- PHPStan拡張として `MetaBag::get()` と `OptionAccess::get()` の戻り値型推論、`MetaKeyOwnershipRule`、`MetaSchemaReflector` を追加し、`packages/core/extension.neon` から読み込むよう配線した。
- Discoveryの `#[OptionSchema]` ターゲット検証をenum case用に修正し、誤警告を回帰テストで固定した。

## 受け入れ基準チェック

- ✔ `#[MetaSchema]` の type/default/single/showInRest/description/sanitize は統合テストで `get_registered_meta_keys()` の登録引数を検証した。
- ✔ default型不一致、single=false+default、sanitize形式不正、空キーは `MetaSchemaDefinitionTest` で `InvalidSchemaException` を検証した。
- ✔ 同一スコープの重複キー、subtype違いの同名キー共存、`markExternallyManaged()` 済みキーのPHP宣言拒否は `MetaSchemaRegistryTest` で検証した。
- ✔ `MetaBag` の解決順、single=falseの複数行、宣言済みキーだけの `all()` はユニットテストで検証した。
- ✔ `ValueCaster` の主要キャスト表と default互換判定は `ValueCasterTest` で固定した。
- ✔ `WpMetaStorage` は統合テストで raw default 非介在、has/get分離、getMultiple、delete冪等性を検証した。
- ✔ `#[UseMetaStorage]` の指定storage経路、不正storageClassの例外、属性なし時の `WpMetaStorage` 経路を検証した。
- ✔ `ObjectType::resolveId()` のID<1と種別不一致は統合テストで `InvalidArgumentException` を検証した。
- ✔ `#[WithMetaRevisions]` の `revisions_enabled => true` 登録と不正付与の例外を検証した。
- ✔ `OptionAccess` の `name()` / `deleteAll()`、`OptionRepository` のprefix/default/autoload、`WpOptionStorage` の null/false/空文字保存は統合テストで検証した。
- ✔ Option enumのスキーマ収集は `ReflectionEnum::getCases()` 経路で実装し、string backedでないenum・`#[AsOptionGroup]` 欠落はユニットテストで `InvalidSchemaException` を検証した。
- ✔ PHPStan拡張は `TypeInferenceTestCase` と `RuleTestCase` で、MetaBag/Option getter型推論、他エンティティ定数混入、宣言済みキーの文字列直書きを検証した。
- ✔ 本層は `composer analyse` level max / baselineなしを通過した。
- ✔ マジックメソッド、`extract()`、グローバルフィルタによるstorage差し替えはコード上に存在しない。

## 追加確認

- 文書04では旧案の `PreviewMetaSupport::enableFor()` は廃止され、`#[WithMetaRevisions]` + WordPress 6.4 の `revisions_enabled` が正準。コア独自のプレビューフックは実装していない。
- WordPressテスト環境では既に `init` が発火済みのため、統合テスト中に `Kernel::boot() was called after the 'init' hook had fired` のログが出る。既存M2同様、`debug=false` のcatch-up経路を検証対象として扱っている。
- WordPress metadata APIは `false` / `null` をDB上で空文字へ正規化するため、`WpMetaStorage` では「行あり」の判定を `has()` で検証し、値そのものの null/false保持は `MetaStorageInterface` のcustom storage経路で固定した。
