## 3. 実装内容の要約

- 対応範囲と開発環境(T1)
  - 全 composer.json の PHP 下限を 8.3 にし、PHPStan の解析範囲を 8.3〜8.5 にした。PHPStan 拡張の設定は `packages/core/phpstan/extension.neon` の 1 つにまとめた。
  - `@wordpress/env` を package.json で 11.17.0 に固定し、composer スクリプトと CI は `node node_modules/@wordpress/env/bin/wp-env` を直接実行する。
  - .wp-env.json に PHP 8.3 と無料版 ACF 6.8.10 を固定した。
  - qa.yml の unit を PHP 8.3 / 8.5、integration を PHP 8.3 / 8.5 × WordPress 7.0 / 最新版の 4 セルにした。
- unit と analyse(T2)
  - ユニット用 bootstrap から WP 定数と偽 wpdb を除き、偽 wpdb を WpdbTestDouble に一本化して書き込み失敗(false)を返せるようにした。
  - fixture が WP のクラス・関数をグローバルに定義しないようにし、PHP 8.5 の非推奨で失敗していたテストを公開 API 経由の検証に置き換えた。
  - bin/coverage-check.php の `$argc` / `$argv` をやめ、PHPStan のエラーを解消した。
- 文書(T3)
  - docs/12 を版ごとのロードマップに書き換え、docs/acceptance/ を `v0.x.y.md` 形式の記録の置き場にした。
  - docs/11 からレシピの複製を除き、レシピの正本を各パッケージの rules/ にした。
  - 文書間の食い違い(ブート例のクラス名、ヘルパのファイル名、パッケージ数、ライセンス表記等)を解消した。
- 統合テスト基盤(T4)
  - `tests/fixtures/` の fixture のテーマとプラグインを、WordPress の通常の読み込みで init 前に boot する経路で統合テストを実行する。共通処理は IntegrationTestCase にまとめた。
  - 偽の ACF 関数を廃止し、wp-env に入れた無料版 ACF で検証する。
  - テストライブラリは、wp-env がコアと同じタグから取得する `WP_TESTS_DIR` のものを使う。IntegrationEnvironmentGuard が、開発用サイトのテーブルを壊しうる設定を WordPress の読み込み前に検出して止める。
- 合算カバレッジと外部アクション(T7)
  - bin/coverage-check.php が unit(ホストの PHPUnit 11 と pcov)と integration(wp-env のコンテナ内の PHPUnit 9.6 と Xdebug)の clover をリポジトリからの相対パスに正規化し、行単位で合算して閾値で判定する。閾値は composer.json の `test:coverage:check` の 1 か所にある。
  - qa.yml の `coverage` ジョブ(PHP 8.3 / WordPress 最新版)が合算を判定する。
  - qa.yml と split.yml の外部アクションをコミットの SHA で固定し、行末にタグ名を書いた。split の送り先を `tmstack-io/tmswp-{パッケージ名}` の 7 リポジトリにした。
- 翻訳(T5)
  - tools/build-l10n.php を廃止し、`composer i18n:build` を wp-env の WP-CLI による `make-pot` → `update-po` → `make-mo` → `make-php` に置き換えた。`.l10n.php` は WordPress が読む形式で生成され、ja-toolkit の pot 名は `tmswp-ja-toolkit.pot` になった。
  - Form のルールと KanaTextField の訳を `__('…', 'tmswp')` のリテラル呼び出しにし、`function_exists('__')` による代替経路を削除した。
  - L10nTest は生成物の形式と .po・.pot の一致を検証し、KernelTest はテキストドメインのローダーを実行して検証する。翻訳の統合テスト(TranslationIntegrationTest)を新設した。
  - CI の `coverage` ジョブが翻訳ファイルを再生成し、差分や未追跡のファイルが出ないことを確かめる。

## 6. 次の版へ引き継ぐ事項

- **カバレッジの余裕が小さい。** 合算は 58.38% で、v0.1.0 の基準 58% との差は 0.38 ポイントしかない。v0.2.0 の基準は 61% であり、v0.2.0 のタスクで統合テストを足して引き上げる必要がある。
- **CI の外部アクションと runner の告知。** 全ジョブで、actions/checkout・actions/setup-node・actions/upload-artifact と、ramsey/composer-install が内部で使う actions/cache が Node.js 20 向けで、Node.js 24 で強制実行されているという非推奨の警告が出ている。また、`ubuntu-latest` は 2026-10-19 から Ubuntu 26 へ移行すると告知されている。Node.js 24 で動く版への更新と runner の版の固定は v0.8.0-T6 で行う。それより前に CI が失敗した場合は、その時点で対処する。
- **ローカルで `composer test:coverage` を実行するには pcov が必要。** unit 層のカバレッジはホストの PHP の pcov で計測する(`test:coverage:unit` は `XDEBUG_MODE=off` で実行する)。integration 層は `composer wp:start:coverage` で起動した wp-env の Xdebug で計測する。
- **`function_exists` による黙った代替経路が src に残っている。** WordPress の関数の有無を `function_exists` で確かめて、黙って別の処理に切り替える分岐である(Form の Messages・Rule/Retype の `apply_filters`、Rule/MaxFileSize の `size_format`、FormHtml の `esc_html`、ja-toolkit の `did_action`、acf-bridge の ACF 無効時の早期 return、ヘルパの定義のガード等)。担当の版のタスクの完了条件に入れた(v0.2.0-T2、v0.4.0-T2・T4、v0.6.0-T1・T5、v0.7.0-T2・T3。View と ActionRouter の分は v0.5.0-T1 でファイルごと削除する)。
- **統合テストのメタキーを文字列で書いている。** PHPStan 拡張の MetaKeyOwnershipRule が解析中にテストクラスを読み込もうとして内部エラーで止まるため、`MetaIntegrationTest` のメタキーをクラス定数ではなく文字列で書いた。v0.2.0-T3 で拡張を ReflectionProvider で実装し直し、クラス定数に戻す。
- **無料版 ACF で見つかった AcfMetaStorage の不具合。** ACF が管理しないキーでは削除が失敗して `has()` が true のまま残り、ACF が管理するキーでは未保存でも既定値が返る。該当するテストは統合テストから外してあり、v0.6.0-T2 で直して戻す。
- **ACF Pro 限定機能の確認。** CI は無料版 ACF で確認している。Pro 限定機能の確認は v0.9.0-T1 で行う。
