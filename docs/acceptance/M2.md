# M2 受け入れ記録

実施日: 2026-06-13

## 対象

M2: Entity layer: PostType / Taxonomy / UserRole / Query

## 実装範囲

- `Post\PostTypeDefinition` / `Post\PostType` / `Post\PostQuery` / `Post\Thumbnail` を追加し、投稿タイプ定義、登録、基本クエリ、サムネイル参照を実装した。
- `Tax\TaxonomyDefinition` / `Tax\Taxonomy` / `Tax\TermQuery` を追加し、タクソノミー定義、登録、基本クエリを実装した。
- `User\UserRoleDefinition` / `User\UserRole` / `User\UserQuery` を追加し、ユーザーロール定義、登録、基本クエリを実装した。
- `Label\LabelLanguage` / `Label\LabelGenerator`、`Query\PageResult`、`Entity\EntityReference`、`Entity\WpBridge` を追加し、ラベル生成、ページング結果、FQCN 参照解決、WordPress 境界の呼び出しを分離した。
- `Meta\MetaBag` / `Meta\WpMetaStorage` を追加し、M2 の entity `meta()` 境界で必要な最小限のメタ読み書きを実装した。schema 連携は M3 で拡張する。
- `AsPostType` / `AsTaxonomy` / `AsUserRole` を実初期化クラスへ接続した。
- `Kernel` の delayed boot catch-up 実行で、同一hook内の priority 順が WordPress 通常実行と一致するよう修正した。

## 追加確認

- `AsTaxonomy` は `init` priority 9、`AsPostType` / `AsUserRole` は priority 10 で登録する。
- 統合テストでは WordPress テスト環境の `init` 後 boot を想定し、`debug=false` の catch-up 経路で registration を検証した。
- `ComponentCache` warm path の方針は M1 のまま維持し、キャッシュ復元時に app クラス存在確認は行わない。

## 未達・要確認

- `composer test:coverage` は M0 / M1 と同じくローカル PHP に coverage driver が無いため未実施。CI では pcov を使う想定。
- `MetaBag::all()` と schema default 連携は M3 の Meta / Option schema 実装で仕上げる。
