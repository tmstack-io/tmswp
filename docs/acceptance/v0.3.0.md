## 1. 版の目的

Post/Tax/User/Query/Meta/OptionのWordPressとの結合部の欠陥を直し、WpBridgeを廃止し、Query層をenumで書き直す。あわせて、メタ・設定の使い分け(§1.9)のコア側(`#[MetaSchema]`と`MetaBag`を単純な値の唯一の経路にする)を実装する。

## 3. 実装内容の要約

- メタ・オプション(T1)
  - 書き込みの戻り値を、true(書き込んだ)・false(保存値が変わっていない。同じ値と、ほかのプラグインのフィルタによる中止)・`RuntimeException`(データベースのエラー)の3通りに定めた。判定はWpDatabaseGuardが`$wpdb->num_queries`と`last_error`で行い、書き込み操作の中の読み取りも同じく判定する。受け入れる限界の4件を`04-meta-options.md`に書いた。
  - メタのキーと値を`wp_slash()`してから保存し、バックスラッシュとJSON文字列が往復するようにした。
  - `null`の書き込みを拒否し、宣言した型と値の型を検査する。オプションのnullのセンチネル(WpOptionNullValue)を削除した。
  - `register_*_meta`がfalseを返したら例外にする。非公開の定数への`#[MetaSchema]`を拒否し、`#[OptionSchema]`をenumのケースだけに限った。
  - サブタイプの文字列`'all'`の特別扱いをやめ、`markExternallyManagedInAllSubtypes()`を追加した。`MetaBag::all()`はsingle=falseのキーの全行を返す。`deleteAll()`は実際に削除した名前だけを返す。
  - `04-meta-options.md`とrules(meta・options・acf・extensions)に、メタ・設定の使い分け(§1.9)と、v0.6.0までのACFとの境目を書いた。
- エンティティ定義とファサード(T2)
  - Thumbnailのimg要素の属性を`Support\Html::attributes()`で組み立て、許可されないプロトコルのURLを拒否する。
  - 存在しないbuiltinの投稿タイプ・タクソノミー・ロールのアダプタを、`register()`で例外にする。`UserRole::register()`はKernelを受け取り、登録済みのロールとの差分をwarningで記録する。
  - `Kernel::defer()`(@internal)を追加し、キャッチアップ中もbuiltinタクソノミーの再試行が走るようにした。`use_block_editor_for_post_type`のフィルタはbool以外を受けても落ちない。
  - EntityDataExceptionを追加し、`parents()`の深さの超過を実行時のデータの不整合として扱う(debugは例外、本番はKernelのロガーに記録して空配列)。
- メタ登録のboot時への移動(T3)
  - コアのエンティティのInitializerが、Kernelのbootの中でメタスキーマをMetaSchemaRegistryに登録する。WordPressへの登録(`register_*_meta`)はinit 20で行う。initの前でも、appの`#[Action('init')]`の中でも`meta()`が使える。
  - スキーマは探索結果ファイルのcomponentsのクラスからリフレクションで読み、`#[UseMetaStorage]`と`#[WithMetaRevisions]`を保持する。
  - ACFとの重複は、外部管理の申告と`#[MetaSchema]`の宣言のうち後に起きた側で検出する。`registerAll()`の後の`registerEntity()`と、WordPressへの登録の前のsanitize付きのキーへの書き込みはLogicExceptionにした。
  - ロールの登録をinit 11にして、投稿タイプ(init 10)の後に固定した。
- WpBridgeの廃止(T4)
  - WpBridgeを削除し、WordPressの関数を直接呼ぶ。各`toArgs()`とTermQuery・UserQueryの引数の配列を、stubsの`@phpstan-param`と同じ形の型で宣言した。
  - 任意の引数を足すAPIを`args(array)`・`withArgs(array)`にし、既知のキーを型で検査する。
- Query層の書き直し(T5)
  - PostQuery・TermQuery・UserQueryがCompare・CastType・SortOrderと、新設のTermField・TermOperatorを受け取る。QueryValidatorと、slugから作るクエリのファクトリ(ofType・ofTaxonomy・ofRole)を削除した。
  - 空のIN指定と、`idIn()`から`idNotIn()`を差し引いて空になった場合は、0件と確定させ、WordPressの検索を実行しない。
  - `WP_Error`はWpErrorHandlerの1か所で扱い、debugはQueryException、本番はエンティティのKernelのロガーにerrorで記録して既定値を返す。`\`を含む文字列はクラスの参照として扱い、そのクラスが無ければ例外にする。
  - 件数を指定しない`get()`は全件を返し、`first()`は常に1件を取る。矛盾する指定はInvalidQueryException、値の誤りはInvalidArgumentExceptionにする。`orderByMeta()`はメタを持たないレコードを落とさずに並べる。
- 受け入れテストとrules(T6)
  - 統合テストでinitの前にKernelをbootし、`do_action('init')`で登録を進める基盤(BootsKernelBeforeInit)を足した。`MetaStorageInterface`の契約を抽象テストケースにした。`03-entities.md` §16と`04-meta-options.md`の受け入れ基準の全項目にテストを対応させた(5.2の条件1の表)。
  - rules/user-role.md(認証のレシピを含む)を新設し、post-type・taxonomy・meta・optionsにbuiltin・既定値・未宣言のキー・テスト・クエリの規則を足した。
  - 対象領域を再点検して見つけた不具合を直した。`create()`のslash(PostType・Taxonomy・UserRole)、`PostQuery::author()`の0と負の値、`#[WithMetaRevisions]`のプレビューの偽の値、String型の`Stringable`、`parents()`の祖先がちょうど100件の場合、`UserQuery::search()`の列(UserSearchColumn)、`#[AsOptionGroup]`の無いenumのケースへの`#[OptionSchema]`、`rewriteSlug()`の例外の文言。
- テストでのストレージの差し替えと、単独の読み取りのデータベースのエラー(T6の追加分)
  - 既定のストレージを`MetaStorageInterface`・`OptionStorageInterface`のidで解決する。拡張の`register()`で登録した実装をbootの中で固定し、無ければWpMetaStorage・WpOptionStorageを使う。bootの後の差し替えと、interfaceを実装しない登録はContainerExceptionにした。WpMetaStorage・WpOptionStorageはコンストラクタで所属するKernelを受け取る。
  - 単独の読み取りのデータベースのエラーは、debugでは例外、本番ではKernelのロガーにerrorで記録して既定値を返す。書き込み操作の中の読み取りは、これまでどおり例外にする。
  - データベースのエラーを検出したら、WordPressが失敗した読み込みで書いたキャッシュ(メタの`{$meta_type}_meta`、オプションの`notoptions`と空の`alloptions`)だけを消す。
  - 契約テストを、データベースに依存しないtrait(`MetaStorageContract`)とデータベース用の抽象クラス(`MetaStorageContractTestCase`)に分け、メモリの実装のユニットテストを足した。
