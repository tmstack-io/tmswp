# M8 acf-bridge acceptance

## 実装内容

- `tmswp/acf-bridge` のM0ダミーを撤去し、`AcfBridge::boot()` / `BridgeConfig` / `AcfFieldAccess` / `AcfMetaStorage` / `PreviewAcfSupport` を実装した。
- acf-json 読み込み用に `AcfJsonRepository` / `FieldGroup` / `FieldDefinition` を追加し、フィールドグループ、ACF options page JSON、`modified` 除外 source hash を扱えるようにした。
- `LocationResolver` / `TargetKind` / `GenerationTarget` と `TypeMapper` を追加し、post/term/user/options のターゲット解決、主要ACFフィールド型の getter/setter 型解決を実装した。
- `Generator` と `wp tmswp acf sync|check` 用 `AcfCommand` を追加し、`*Fields.php` / `*Options.php` / `AcfManifest.php` を決定的に生成できるようにした。
- `CloneResolver` を追加し、clone の seamless / prefix_name / group 表示展開、参照未解決 E004、循環参照 E005 を固定した。
- `LocationResolver` に W003/W004/W006/W007 の詳細警告を追加し、`check --strict` の警告対象にした。
- `AcfFieldAccess` に `AcfImage` / `AcfFile` 用のshape検証ヘルパを追加し、生成コードがPHPStan上でも `AcfImage|null` / `AcfFile|null` を返せるようにした。
- `AcfManifest` 生成物を実行時の `init` priority 6 で `MetaSchemaRegistry::markExternallyManaged()` へ流し、ACF管理下キーの `register_*_meta` スキップと重複検出へつなげた。
- `MetaSchemaRegistry` に `schemas()` と `objectSubtype=all` の外部管理判定を追加し、`wp tmswp acf check` 側の E101 静的重複検出に使えるようにした。
- `packages/acf-bridge/composer.json` は ACF を require せず `suggest` のみとした。
- `starters/theme` / `starters/plugin` に `acf:check` を追加した。

## 設計判断

- 生成物の source hash は仕様どおり `AcfManifest.php` のみに入れ、通常の accessor class には入れない。
- `AcfMetaStorage::get()` は `get_field(..., false)` の raw 値だけを返す。フォーマット済み値は生成アクセサへ分離した。
- ACF未導入環境でも `AcfBridge::boot()` は成功させ、値アクセス時だけ `AcfNotActiveException` にする。
- clone はサイレントに `mixed` 化せず、解決不能・不正形式・循環を E004/E005 で明示する。
- 実行時の Manifest はキャッシュファイルを持たず、生成済み `AcfManifest.php` と composer autoload に一本化した。
