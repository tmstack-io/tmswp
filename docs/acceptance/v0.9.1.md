本書は、ロードマップ(`../12-implementation-plan.md`)のv0.9.1(§3.2)について、全版に共通する受け入れ条件(§0.3)とこの版の受け入れ条件を確認した結果を記録する。今はv0.9.1-T0(版の準備)の分だけを書いている。T1〜T4の確認の結果と、受け入れ条件ごとの検証結果は、各タスクとT5が書き足す。

## 1. 版の目的

導入先が最初に詰まりやすい本番へのデプロイの手順と、RESTルートの手本をレシピにする。配布物のコメント・文書から、利用者の手元に無い設計文書と、公開していない決定の番号への参照を除く。あわせて、v0.9.0から引き継いだ事項(`v0.9.0.md` 6章)のうち、自分たちで直せるもの(PHPStan 2.3、手元のテストの件数、スターターの`SimpleLogger`)を片付ける。

## 3. 版の準備(T0)

### 3.1 版の箇所

1つのコミットで、次を0.9.1に上げた(`../RELEASING.md`の手順2)。packages/*のbranch-aliasは`0.9.x-dev`のままである。

- `Kernel::VERSION`を`0.9.1`にした。
- packages/*・starters/*・examples/sample-siteのcomposer.jsonの`tmswp/*`の制約(`require`と`require-dev`)を`^0.9`から`^0.9.1`にした(PATCHが0より大きい版の形)。
- examples/sample-siteのpathリポジトリの`versions`(6つ)を`0.9.1`にした。
- 版の例(packages/*/README.mdの要件の行、examples/sample-site/README.md、docs/01・02・08・11)を0.9.1と`^0.9.1`にした。docs/10には、版の例として今の版を示す箇所が無かった。
- tests/Unit/PackageManifestTest.phpの`testComposerManifestsMatchThePackageTableOfDocs01`は、docs/01 §3.1の表の`^X.Y`を`^<MAJOR>.<MINOR>`の文字列に置き換えて照合していたため、制約が`^0.9.1`になると失敗した。今の版の制約を`Kernel::VERSION`から求める補助(`currentConstraint()`。PATCHが0なら`^X.Y`、0より大きければ`^X.Y.Z`で、リリースの前の検査の`requiredConstraint()`と同じ規則)を足し、このテストと`testExtensionManifestFollowsCommonConvention`の制約の照合を、その補助との完全一致にそろえた。docs/01 §3.1の表の下の説明にも、PATCHが0より大きい版では`^X.Y.Z`であることを書いた。
- tests/Unit/PackageManifestTest.phpとdocs/01 §3.1の表の下の説明は、T0の対象ファイル領域に無いが、パッチの版の制約(`^X.Y.Z`)を初めて使ったことで直す必要が生じたため、版の引き上げと同じ変更で直した。
- 版の上げ方を、リリースのときに道具が書き換える、またはリリースのたびに更新するとしていた古い記述を、今の運用(版の最初のタスクで手で上げ、リリースの道具は書き換えず、リリースの前の検査がタグの版との一致を確かめる)に直した。直したのは、docs/11 §8.2のスターターのcomposer.jsonの説明(`tmswp/core`の制約)、docs/02の`Kernel`のコードの写しのdocblockと§3.9の`Kernel::VERSION`の項、packages/core/src/Kernel/Kernel.phpの`VERSION`のdocblockである。
- CHANGELOG.mdの先頭(説明文の後、`## v0.9.0 — 導入できる版`の前)に`## Unreleased`の節を開き、版の引き上げを「変更」に書いた。

  - 範囲外の古い記述として残す(T4か別のタスクで直す):

## 4. 上流の更新を待つ事項の確認(T0。§3.5)

2026-10-30に、GitHubのAPI(`gh api`)、npmのレジストリ(`npm view`と、`npm audit`が使う勧告のAPI`https://registry.npmjs.org/-/npm/v1/security/advisories/bulk`)、手元の`npm audit`で確かめた。3つとも、回避を外せる更新は出ていなかった。docs/12 §3.2にタスクは足していない。

| 事項 | 確かめた方法 | 結果 | 扱い |
|---|---|---|---|
| WP-CLIのPHP 8.5の非推奨 | `gh api repos/wp-cli/wp-cli/releases`・`repos/wp-cli/wp-cli-bundle/releases`、wp-cli-bundleのcomposer.lock(タグ`v2.12.0`と`main`)、php-cli-toolsの`lib/cli/Colors.php`のコミットの履歴、ルートのwp-envのcliコンテナでの`wp cli version` | WP-CLIの最新の版は2.12.0(2025-05-07)のままで、同梱のphp-cli-toolsはv0.12.5である。php-cli-toolsの修正(#188「Fix `null` array access in `Colors.php`」、2025-09-11)はv0.12.6以降に入り、wp-cli-bundleの`main`(nightly)のlockはv0.13.2だが、それを同梱した安定版は出ていない。wp-envのcliコンテナのWP-CLIは2.12.0 | 更新なし。`WpCliPharDeprecations`を使い続ける |

| `npm audit`の残り | ルート・examples/sample-site・starters/themeで`npm audit --json`、`npm view`で依存の最新の版と依存の範囲、勧告のAPIで勧告の対象の版 | 件数と重大度はv0.9.0のT5の時点と同じ。ルートは1件(qsのmoderate。勧告はGHSA-x5fp-wj9c-mxmx・GHSA-4mjr-xmp4-gh2g・GHSA-6pq8-jhm2-2vcw)。examples/sample-siteとstarters/themeは12件ずつ(low 6・moderate 5・high 1)で、highはserialize-javascript(GHSA-5c6j-r48x-rmvq等) | 更新なし。下の詳細のとおり、上流の依存の範囲で直せる版が無い |

`npm audit`の詳細は次のとおりである。

- ルートのqs: 該当するのは`@wordpress/env` 12.0.0 → `@wp-playground/cli` 3.1.61(最新の版) → express 4.22.2(`@wp-playground/cli`が版を固定) → qs 6.15.3(expressの範囲は`~6.15.1`)である。qsは2026-10-27に6.15.4・6.16.2等を出したが、勧告のAPIはGHSA-4mjr-xmp4-gh2gの対象を`>=2.2.5 <6.16.0`としており、`~6.15.1`の範囲に勧告の外の版が無い。express 4.22.3は`~6.16.0`を使うが、`@wp-playground/cli`の最新の版が4.22.2に固定している。`npm audit --json`のqsの`fixAvailable`は真を返すが、上の範囲のとおり、依存の範囲の中で勧告の外の版に上げる道は無い。
- examples/sample-siteとstarters/themeのserialize-javascript: `@wordpress/scripts`の最新の版は、両方が固定している37.0.0(2026-10-20)である。37.0.0は`copy-webpack-plugin`の`^10.2.0`に依存し、それがserialize-javascriptの`^6.0.2`(入っているのは6.0.2)に依存する。勧告の外の版は7.1.3以上で、copy-webpack-pluginは14.0.0で`^7.0.3`に上げているが、`@wordpress/scripts`はまだ取り込んでいない。`npm audit`が示す直し方は`@wordpress/scripts` 35.0.0への下げ(SemVerのメジャー)で、上流の更新ではない。
