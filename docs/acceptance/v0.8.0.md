## 3. 実装内容の要約

- 計画の補正(T0)
  - 着手前の調査に合わせて、docs/12のv0.8.0の節の対象ファイル領域と完了条件を補正し、T1〜T8を逐次にした。台帳で件数だけ分かっていたA7のlowの4件を、再点検で特定してT3・T6に振り分けた。
- 独自ブロックの自動登録(T1)
  - 探索コマンドとdebugのbootが、テーマ・プラグインのルートの`build/blocks/`以下(入れ子を含む。ソースの`blocks/`は含まない)の`block.json`を走査する(`Block\BlockScanner`)。Kernelは`init`の10で`register_block_type()`に`block.json`のディレクトリを渡して登録する(`Block\BlockRegistrar`)。
  - 探索結果ファイルをschema 5にし、`blocks`(name・path・metadataHash)を足した。`block.json`だけを変えて作り直さないと、`wp tmswp discover --check`が失敗する。
  - Kernelの中のブロック名の重複・未登録のカテゴリ・壊れたJSON・nameの形の誤りは探索コマンドの`DiscoveryException`、Kernelをまたぐ名前の重複・コア等との重複・探索結果ファイルと食い違うnameは`KernelException`にした。
  - `KernelConfig::theme()`・`plugin()`の`blockCategories`(`Block\BlockCategory`)と、`PostTypeDefinition::allowedBlocks()`(`allowed_block_types_all`でその投稿タイプにだけ反映し、先に動いたフィルタの制限を広げない)を足した。packages/core/rules/blocks.mdを新設した(台帳A8-06)。
- スターター(T2)
  - `bin/setup.php`(テーマとプラグインで同じ内容)を作り直し、スラッグからStudlyCaseの名前空間を作って、composer.jsonのpsr-4・name(`local/<slug>`)・license(`proprietary`)、本体ファイルの名前(`plugin.php`→`<slug>.php`)、app/の名前空間、AGENTS.md、ブロック名、README.mdを書き換え、最後に自分を消す。値は引数・環境変数・対話の順に探し、端末が無く値が欠けていればエラーで止まる。
  - post-create-project-cmdを`setup.php`と`composer dump-autoload`の2つにし、`config.autoloader-suffix`を生成した名前空間にした。同じ版のスターターから作ったプラグイン2本を同じサイトで有効にしても、オートローダのクラスが重複しない(台帳A7-06・A7-18)。
  - スターターのlicenseをGPL-2.0-or-later(D-52)、ラベル言語の既定を日本語にした。テーマのスターターにブロックの例(`blocks/example`)とビルドした出力(`build/blocks`)を置き、package.jsonの`build`でビルドと探索コマンドを続けて実行する。各スターターの探索結果ファイルをコミットし、スターターの`composer qa`に`discover:check`を入れた。スターターのCLAUDE.mdを削除した。
  - スターターから作ったテーマ1つとプラグイン2本が同じサイトで別々のKernelとして起動し、フロントがHTTP 200を返すことを確かめる統合テスト(tests/Integration/、testsuite starters)を足した。
  - coreの`KernelConfig`のTMSWPの予約の判定と、Kernelの名前空間の重複・入れ子の判定を、大文字と小文字を区別しない比較にした。

## 6. 次の版へ引き継ぐ事項

1. **スターターから作ったプロジェクトの`composer qa`は、テストを1件も実行しない(`No tests executed!`)。** スターターのtests/Unit/は`.gitkeep`だけで、PHPUnit 11は0件でも成功で終わる。CIのStarter Projectsが実質的に確かめているのは、lint・analyse・`discover:check`までである。スターターにテストの例を置くかを、v0.9.0で決める。
