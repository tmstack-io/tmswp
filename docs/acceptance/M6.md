# M6 Model layer acceptance

## 実装内容

- `Connection` / `TableDefinition` / `QueryBuilder` / `Model` / `Migrator` / `MigrateCommand` を追加した。
- `#[AsModel]` を `ModelInitializer` に接続し、Kernel のコンテナへ `Connection` と `Migrator` を登録した。
- `Compare` / `CastType` / `SortOrder` と、Model 層用の例外を追加した。
- `dbDelta` 互換のテーブルSQL生成、スキーマハッシュ保存、強制migration、dry-run、残存スキーマ検証を実装した。
- スターターのテーマ/プラグインに `#[AsModel]` の最小モデル例を追加した。

## 設計判断

- SQL識別子は `Identifier` で検証し、値は `Connection::prepare()` の境界でプレースホルダー数とバインド可能型を検証する。
- `QueryBuilder` の raw API は quote/backtick/semicolon を拒否し、placeholder数の不一致を即時例外にする。
- `whereIn([])` は `0 = 1`、`whereNotIn([])` は `1 = 1` に固定した。
- `update()` / `delete()` は WHERE なし、join/group/order/limit/offset/alias 付きでは実行しない。
- DTO hydration は不足列や不正型を補完せず、`HydrationException` で失敗させる。配列型はJSON文字列のみ受ける。
- `Model::insert([])` は空INSERTを明示SQLで発行し、それ以外は `Connection::insert()` に委譲する。
- `Migrator::listen()` は `tmswp/activated` で強制migration、`admin_init` priority 5 で通常migrationを実行する。管理画面では `MigrationException` のみ捕捉して `wp_admin_notice` と `wp_trigger_error` に流す。
