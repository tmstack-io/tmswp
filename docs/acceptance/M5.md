# M5 受け入れ記録

実施日: 2026-06-13

## 対象

M5: Form layer

## 実装範囲

- `FormStep` / `FormAction` / `FieldType` enum、`Field`、`FormDefinition`、`FormRequest`、`FormResult` を追加し、フォーム定義・入力束縛・結果状態を接続した。
- `RuleInterface` / `Rule` / `Validator` / `ValidationContext` / `Messages` と、`Required` / `RequiredIf` / `MaxLength` / `MinLength` / `Email` / `Url` / `Regex` / `Choice` / `Callback` / `Retype` / `Range` / `UploadFile` / `FileExtension` / `MaxFileSize` を追加した。
- `CompositeField`、`DateSelectField`、`KanaTextField` / `KanaType` を追加し、複合入力の部分検証、日付妥当性、かな変換を実装した。
- `ConfirmToken` / `ConfirmTokenResult` / `ConfirmTokenStatus` と `JtiStore` を追加し、HMAC署名、canonical JSON、期限判定、form id照合、jti再送信防止を実装した。
- `UploadedFile` / `StoredFile` / `TempFileStore` を追加し、一時ファイルtoken、metadata復元、moveTo/toAttachment、GC、保護ファイル生成を実装した。
- `Form` を final concrete として追加し、GET/非対象POST、CSRF失敗、Confirm、Submit、Back、確認なしSubmit、期限切れ、jti重複、idempotent handle を状態機械として実装した。
- `FormHtml` / `FieldView` / `OptionView` を追加し、HTML生成、選択肢、エラー、確認画面表示、file token hidden を純粋なエスケープ済み出力として実装した。
- `starters/theme/actions/contact.php`、`contact.php`、`parts/contact-form.php` を追加し、actionsからFormを生成してテンプレートへ渡す正準fixtureを用意した。

## 受け入れ基準チェック

- ✔ `Field` は名前規約、予約名、`__token` suffix、空choices、rules/filters型を設定時に検証する。
- ✔ text/textarea は半角・全角空白をtrimし、checkbox未送信は `''`、checkboxes未送信は `[]` として束縛する。
- ✔ `Validator` は空値スキップ、複数値の各要素検証、選択肢不正、全ルールのメッセージ、`apply_filters('tmswp/form/rule_message', ...)` をユニットテストで固定した。
- ✔ `RequiredIf` と `Retype` は別フィールド値とラベルを `ValidationContext` から参照し、未知フィールドは定義エラーへ倒す。
- ✔ `DateSelectField` は未入力・部分入力・不正日付・正規 `Y-m-d` 値への変換を検証した。
- ✔ `KanaTextField` は `mb_convert_kana` による正規化後に `Regex` / `MaxLength` を適用する。
- ✔ `ConfirmToken` は改ざん、署名切り詰め、form id不一致、期限切れ、不正payload形を検証した。
- ✔ `JtiStore` は `INSERT IGNORE` と `rows_affected === 1` でjtiを消費し、同一tokenの二重Submitを拒否する。
- ✔ `Form::handle()` は GET、非対象POST、CSRF失敗、未知step、確認なしConfirm、Confirm→Submit、Invalid/Expired token、Back、jti重複、idempotentを検証した。
- ✔ `UploadedFile` は本物のPHP uploadだけを有効扱いし、通常ファイルをアップロード扱いにしない。
- ✔ `TempFileStore` はtoken正規表現、壊れたmetadata、resolve、moveTo、delete、GC、`.htaccess` / `index.html` 生成を検証した。
- ✔ `FieldView` / `OptionView` / `FormHtml` はHTML属性・本文・選択肢ラベル・エラー・file token hiddenをエスケープ済みで出力する。
- ✔ スターターのテーマfixtureは `actions/contact.php` でFormを生成し、`parts/contact-form.php` が `Form` インスタンス以外を受け取った場合に即時例外へ倒す。
- ✔ WordPress統合テストで、テーマactionから生成したFormをテンプレートで描画し、プラグインfallback templateでもFormコントロールを描画できることを確認した。

## 追加確認

- `Messages` は静的メッセージレジストリを持たず、ルール既定/カスタムメッセージ、WordPress filter、placeholder置換の順で解決する。
- `ConfirmToken` のpayloadはcanonical JSONで署名し、値形が `string` / `list<string>` / `array{__tmsfile: string}` 以外なら `Invalid` として扱う。
- `TempFileStore` は `wp_upload_dir()` / `sanitize_file_name()` が利用できない場合に例外を投げ、別ディレクトリや通常ファイル移動へ暗黙に切り替えない。
- `StoredFile::moveTo()` は `wp_unique_filename()` が利用できない場合に例外を投げ、上書きや独自命名へ暗黙に切り替えない。
- `Form` のnonce検証はPOSTかつ対象フォームの場合だけ実行し、`wp_verify_nonce()` が無い場合は設定エラーにする。

## 未達・要確認

- `composer test:coverage` はローカルPHPに coverage driver が無いため失敗。CIでは pcov か xdebug を有効化して確認する想定。

# 2026-07-05 再編: Form プリセット配置と既定メッセージの英語ソース化

## 実装内容

- core の `packages/core/src/Form/Composite/` から `DateSelectField` / `KanaTextField` / `KanaType` を削除し、`CompositeField` のみを残した。
- `CompositeField` に `validateParts()` / `invalidPartsMessage()` を追加し、日付のようなパーツ間整合性を抽象側で扱えるようにした。
- カナ入力は `tmswp/ja-toolkit` の `TMSWP\JaToolkit\Form\KanaTextField` / `KanaType` へ移設した。
- 生年月日 select は `packages/core/rules/form.md` と `docs/11-ai-docs.md` の `BirthDateField` レシピへ移した。
- Form 既定メッセージとファイルアップロードエラーのソース文字列を英語化し、日本語訳を `packages/core/languages/` の翻訳ファイルへ収録した。
- `FieldView::display()` の既定区切りを英語ソース `', '` + ja 翻訳 `、` に変更した。

## 設計判断

- 旧プリセット名や互換 alias は追加せず、core は汎用抽象、ja-toolkit は日本語入力プリセット、日付 select は app 側レシピという単一状態にした。
- `DateSelectField` 固有分岐を `Validator` に残さず、`CompositeField` のパーツ検証契約へ移した。
